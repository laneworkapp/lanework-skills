# Corners of the space

Every corner gets ≥1 map branch, or an explicit out-of-scope line with why. Floor, not ceiling: a project-specific corner (migration, pricing, compliance) gets its own branch.

| corner | settles |
|---|---|
| Problem | what hurts, for whom, how you'd know it stopped |
| People | users, operators, payers, dependents; what each needs |
| Domain | concepts, names, relationships, rules the domain imposes regardless of software |
| Scope | in, explicitly out, deferred |
| Behavior | what it does step by step, incl. failure + edge cases |
| Constraints | regulatory, contractual, budget, timeline, platform, immovable systems |
| Architecture | solution shape, boundaries, tech choices with lock-in |
| Integrations | every system across a boundary; who owns the contract |
| Data | what's stored, source, who sees it, retention |
| Risks | what sinks it, unknowns, what must be true to succeed |
| Success | how the result is judged; what counts as done |
